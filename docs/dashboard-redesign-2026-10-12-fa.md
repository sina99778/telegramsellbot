# بازطراحی مدیریت وب — ۱۲ اکتبر ۲۰۲۶

سبک انتخاب‌شدهٔ کاربر: متراکم و حرفه‌ای برای اطلاعات زیاد. بازطراحی در پروژهٔ Vue موجود انجام شده و شامل قاب مشترک همهٔ صفحه‌ها، صفحهٔ ورود و مرکز عملیات تازه است.

## تغییرات قابل استفاده

- منوی گروه‌بندی‌شده، عنوان مسیر، اعلان تعداد رسیدهای منتظر و هشدار اختلال سرور.
- ظاهر فشرده با جدول‌های کم‌فاصله، دو حالت روشن/تاریک و انتخاب تراکم؛ فقط ترجیحات ظاهری در مرورگر ذخیره می‌شوند.
- جست‌وجوی سریع با Ctrl+K یا Cmd+K: صفحه‌ها و کاربران واقعی از API؛ بازشدن مستقیم پروفایل کاربر؛ کنترل با فلش‌ها، Enter و Escape.
- مرکز عملیات: شش شاخص، صف رسیدهای بانکی و پرداخت‌های باز، سلامت ثبت‌شدهٔ سرورها، کانفیگ فعال/سقف و فعالیت‌های اخیر.
- بازهٔ ۷/۳۰ روز برای نمودارها؛ نمایش اعشار مبالغ در tooltip؛ به‌روزرسانی اختیاری هر ۶۰ ثانیه؛ خروجی CSV آمار.
- فیلتر سلامت و جست‌وجوی سرورها با پشتیبانی از وضعیت‌های healthy/unhealthy و ok/error.
- جدول کاربران با انتخاب ۲۵/۵۰/۱۰۰ ردیف، پاک‌کردن فیلترها و خروجی CSV همان صفحه. متن‌های قابل کنترل کاربر در CSV از اجرای فرمول Excel محافظت می‌شوند.
- صفحه‌بندی واقعی صف پرداخت‌ها و رسیدها؛ جست‌وجوی نام، یوزرنیم، تلگرام یا شناسهٔ رسید در کل فهرست فیلترشده.
- چیدمان موبایل با منوی کشویی، فوکوس کنترل‌شده و پیمایش مستقل جدول‌ها. Canvas نمودار هنگام تغییر اندازه باعث پیمایش افقی کل صفحه نمی‌شود.

## تغییرات backend و رفتار داده

مسیر محافظت‌شدهٔ `GET /api/dashboard/overview/operations` تعداد واقعی صف‌ها را بدون سقف فهرست‌های قدیمی محاسبه می‌کند. آمار سرور، اینباند و کانفیگ در یک query گروه‌بندی‌شده گرفته می‌شود؛ مجموعاً دو query برای این endpoint و بدون درخواست اتصال مستقیم به پنل‌ها. تعداد اینباندها DISTINCT است تا با پیوستن چند کانفیگ، چندبار شمرده نشوند.

مسیرهای `/receipts` و `/transactions/pending` اکنون `page` و `page_size` دارند و `total_pages` برمی‌گردانند. اندازهٔ صفحه حداکثر ۲۰۰ است. مقدار پیش‌فرض قدیمی ۲۰۰/۱۰۰ حفظ شده؛ رابط جدید اندازهٔ صفحهٔ انتخاب‌شده را ارسال می‌کند. مرتب‌سازی با شناسهٔ پرداخت تکمیل شده تا رکوردهای هم‌زمان ترتیب پایدار داشته باشند.

این توسعه migration تازه نمی‌خواهد. frontend و backend باید با هم به‌روز شوند. منطق و دسترسی‌های تأیید، رد، شارژ و بازپرداخت عوض نشده‌اند. سلامت، وضعیت ثبت‌شده در دیتابیس است و تست زندهٔ اتصال محسوب نمی‌شود.

در قطع API، خطا و هشدار تازگی اطلاعات نشان داده می‌شود و دادهٔ قبلی به‌عنوان مقدار تازه یا صفر جا زده نمی‌شود. درخواست‌های داشبورد با `cache: no-store` ارسال می‌شوند. دادهٔ عملیات در خروج از پنل پاک می‌شود و پاسخ‌های قدیمی پس از لغو درخواست نمی‌توانند وضعیت جدید را بازنویسی کنند.

## اعتبارسنجی

- build با vue-tsc و Vite موفق.
- کل تست‌های Python: ۷۶۲ موفق؛ دو تست PostgreSQL از قبل، بدون دیتابیس آزمایشی اجرا نشدند.
- ۵ تست Node برای CSV، حفظ مقادیر منفی، متن فارسی و مسیرهای جست‌وجو موفق.
- ۶ تست تازهٔ backend برای شمارش بیش از سقف قدیمی، شمارش گروهی سرورها، محافظت دسترسی، صفحه‌بندی و اعتبارسنجی اندازهٔ صفحه موفق.
- مرورگر با دادهٔ آزمایشی: جست‌وجوی کاربر، Ctrl+K و Escape، ماندگاری حالت روشن، تغییر تراکم، نمایش/پنهان‌کردن رمز، فیلتر سلامت، بازهٔ نمودار، دانلود CSV، صفحهٔ دوم صف ۵۰۳ پرداخت و جست‌وجوی رسید بررسی شدند.
- عرض‌های ۱۲۸۰ و ۳۹۰ پیکسل بررسی شدند؛ در موبایل عرض پیمایش کل صفحه با عرض قابل نمایش برابر شد و جدول ۶۴۰ پیکسلی در ناحیهٔ داخلی ۳۴۹ پیکسلی پیمایش می‌شود.
- قطع عمدی سرور پیش‌نمایش آزمایش شد: پیام خطا و هشدار دادهٔ قبلی نمایش داده شدند و شمارش قبلی اشتباهاً صفر نشد.

پنل واقعی، دادهٔ واقعی و اجرای queryها روی PostgreSQL تولید در این مرحله بررسی نشده‌اند. تصویرهای پیش‌نمایش از دادهٔ ساختگی‌اند.

## اجرای پیش‌نمایش آزمایشی

در پوشهٔ `dashboard`:

```sh
npm run build
npm run preview:fixtures
```

نشانی: `http://127.0.0.1:4175/dashboard/`. سرور فقط روی loopback گوش می‌دهد، ورود آن ساختگی است و عملیات نوشتن کسب‌وکار را رد می‌کند. این ابزار مخصوص توسعه است و داخل bundle یا تصویر runtime تولید وارد نمی‌شود. برای استفادهٔ واقعی، frontend به API پروژه و نشست واقعی مدیر وابسته است.

```sh
npm test
python -m pytest -q tests/test_dashboard_operations.py
```

دستور Python باید از ریشهٔ پروژه اجرا شود.
