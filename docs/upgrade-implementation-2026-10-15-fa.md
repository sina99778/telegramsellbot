# وضعیت اجرای ارتقا — ۱۵ اکتبر ۲۰۲۶

این بسته، اصلاح کد و تست است. نصب گواهی، تغییر تنظیمات پنل خارجی، استقرار روی VPS و تأیید علت قطعی دوره‌ای، به محیط اجرایی مربوط‌اند و با تغییر مخزن به‌تنهایی انجام نمی‌شوند.

## مهاجرت و استقرار

مهاجرت افزایشی `scripts/migrations/007_panel_sync_outbox.py` پنج ستون وضعیت/نسخه به `subscriptions` اضافه می‌کند و مسدودسازی‌های قدیمی دارای نگاشت را یک بار برای اعمال مجدد صف می‌کند. سوابق پول و سفارش بازنویسی یا حذف نمی‌شوند. داده درخواست در همان سطر اشتراک نگهداری می‌شود؛ جدول/پردازش جداگانه‌ای به زیرساخت اضافه نشده است.

**این بسته به استقرار کامل نیاز دارد.** bot، API و worker باید با هم متوقف، migration اجرا و هر سه با نسخه جدید راه‌اندازی شوند. اجرای هم‌زمان worker قدیمی و نسخه جدید مجاز نیست؛ نسخه قدیمی از قرارداد outbox و شمارنده نسخه اطلاع ندارد. مسیر `deploy.sh full` همین توقف و اجرای migration را انجام می‌دهد. restart/reload صرف جای migration را نمی‌گیرد.

با برگشت به کد قبلی، داده‌های ستون جدید حذف نمی‌شوند، ولی آن نسخه درخواست‌های pending را پردازش نمی‌کند. rollback باید با بررسی و تعیین تکلیف این درخواست‌ها انجام شود؛ صرف راه‌اندازی worker قدیمی یک rollback کامل کسب‌وکار نیست.

حد حجم Nginx برای کانفیگ‌های نصب تازه یا بازتولیدشده اعمال می‌شود. در سرور دارای کانفیگ قدیمی، تنظیم فعال Nginx باید جداگانه اصلاح و با `nginx -t` تأیید شود.

## وابستگی‌ها

- Python: شاخه‌های آسیب‌پذیر قبلی با `cryptography >=50.0.2,<51` و `Pillow >=12.3,<13` جایگزین شدند؛ pytest و pytest-asyncio نیز ارتقا یافتند.
- داشبورد: Vue، Vite 8، plugin-vue 6، vue-tsc 3 و Tailwind 4 با lockfile تازه؛ build image و CI از Node 24 استفاده می‌کنند.
- تنظیم PostCSS و ورودی CSS برای Tailwind جدید اصلاح شده؛ تنظیم رنگ/فونت موجود حفظ می‌شود. ظاهر اصلی در مرورگر با داده ساختگی بازبینی شد.
- Tailwind جدید مرورگرهای جدید می‌خواهد؛ حداقل‌های اعلام‌شده سازنده Safari 16.4، Chrome 111 و Firefox 128 هستند: [راهنمای رسمی ارتقا](https://tailwindcss.com/docs/upgrade-guide).

اسکن تازه محیط توسعه Python و `npm audit` مورد شناخته‌شده‌ای گزارش نکردند. این نتیجه مربوط به نسخه‌های نصب‌شده در زمان بررسی است، نه تضمین نبود آسیب‌پذیری تازه. image واقعی باید دوباره ساخته شود؛ تغییر فایل وابستگی، بسته‌های داخل image قدیمی را عوض نمی‌کند.

## اعتبارسنجی و محدودیت‌ها

نتیجه محلی مجموعه کامل: **۸۰۴ موفق، ۷ skipped**؛ پنج مورد به PostgreSQL و دو مورد به ابزارهای Linux نیاز دارند. **۱۷ تست جدید خطا/امنیت و ۳ تست restore** موفق شدند؛ build داشبورد، پنج تست ابزارهای رابط و اسکن وابستگی‌ها نیز موفق‌اند.

تست‌های جدید، خرابی/تلاش مجدد پنل، عدم اجرای نوشتن قبل از commit، حفظ اطلاعات Vision، قفل مشغول پرداخت، رد preflight، DNS pinning و SNI، redirect، timeout Redis، پلن زمان نامحدود و restore خراب را پوشش می‌دهند. تست‌های PostgreSQL مستقل، rollback واقعی کیف پول، دیده نشدن intent پیش از commit و رد نوشتن ORM قدیمی را بررسی می‌کنند.

Docker daemon محلی در دسترس نبود؛ تست‌های PostgreSQL برای اجرا در CI دارای سرویس PostgreSQL اضافه شده‌اند. نتیجه CI باید پیش از استقرار بررسی شود. تست restore محلی با بدل فرمان Docker اجرا شد؛ تمرین بازیابی واقعی همچنان لازم است.

بررسی نام‌های تعریف‌نشده/تعارض متغیر در کد اجرایی موفق است و mypy برای چهار فایل اجرایی جدید موفق است. بدهی lint/type کل مخزن جداگانه باقی است؛ مستقل شدن jobها به معنی حذف یا سبز فرض کردن این کنترل‌ها نیست.

## موارد وابسته به سرور و کار باقی‌مانده

1. HTTPS واقعی ساب: endpoint، DNS، گواهی معتبر و پورت صحیح باید آماده و دریافت واقعی ساب آزمایش شود؛ سپس آدرس خروجی تغییر کند. کد، HTTP موجود را بدون آماده بودن TLS کورکورانه عوض نمی‌کند و در فرم مدیریت راهنمای HTTPS اضافه شده است.
2. پنل خارجی: ارتقای خود 3x-ui نیازمند بکاپ قابل بازیابی، آزمایش API/سهمیه/اتصال client و استقرار جداگانه است؛ این بسته نسخه پنل را عوض نمی‌کند.
3. پایش: سلامت worker هنوز باید با سنجش آخرین موفقیت همه jobها، backlog و هشدار عملیاتی تکمیل شود. heartbeat پردازش به‌تنهایی سلامت کسب‌وکار را ثابت نمی‌کند؛ وضعیت/زمان تلاش outbox اکنون برای این پایش قابل مشاهده است.
4. بکاپ: نگهداری نسخه قدیمی DB و snapshot پیش از restore اضافه شده؛ رمزگذاری مستقل آرشیو، مدیریت کلید و تمرین بازیابی عملیاتی هنوز باید اجرا شوند. آرشیو حاوی env باید دسترسی محدود داشته باشد.
5. قطع دوره‌ای: لاگ‌های جدید تشخیص را بهتر می‌کنند؛ بدون لاگ همان رخداد و آزمایش HTTPS/DNS/پنل روی سرور، علت قطعی به مشکل مشخصی نسبت داده نمی‌شود.

مرجع فنی قفل نسخه ORM و محدودیت bulk update: [SQLAlchemy versioning](https://docs.sqlalchemy.org/en/20/orm/versioning.html). نگهداری نام TLS هنگام اتصال به IP ثابت از extension مستند HTTPcore استفاده می‌کند: [HTTPcore extensions](https://www.encode.io/httpcore/extensions/).
